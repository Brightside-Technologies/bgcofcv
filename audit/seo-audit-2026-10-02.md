# SEO audit: Boys & Girls Clubs of Coachella Valley

Audited October 2, 2026. Website: https://www.bgcofcv.org/

Update: the requested High findings and first three Medium findings have now been fixed in the local source. See [implementation and verification results](seo-fixes-2026-10-02.md). The findings below document the original live-site baseline.

The biggest opportunity is to make the existing site clearly describe its youth programs and local clubhouses, repair its metadata, and reduce heavy image content. Its basic crawl infrastructure already works. This report includes proposed optimization copy; no website source or production settings have been changed.

## Scope and evidence

Direct public HTTP checks covered 37 HTML responses, representing 29 public pages plus the CMS login shell after grouping `.html` and extensionless variants. The crawl discovered every HTML entry in the sitemap and the homepage navigation. It also checked 50 additional internal link targets and 86 distinct first-party asset URLs using HEAD requests. All crawled HTML pages returned 200; three additional link targets returned 404. No checked first-party asset returned an error.

The sitemap returned 200 with 90 URLs: 30 HTML entries and 60 PDFs. robots.txt returned 200, allows crawling, and declares the sitemap. HTTP and non-www homepage variants redirect to HTTPS www. A deliberately nonexistent URL correctly returned 404.

Evidence is saved in [crawl.json](evidence/crawl.json), [robots.txt](evidence/robots.txt), [sitemap.xml](evidence/sitemap.xml), and individual HTML snapshots. [crawl.cjs](crawl.cjs) repeats the public checks with `node audit/crawl.cjs` from the repository root. Counts describe this sample; this is not a complete external-link, image-srcset, CSS-background, accessibility, backlink, or browser-rendering audit.

Google's public PageSpeed API returned HTTP 429. No Lighthouse score, measured Core Web Vitals, keyword volume, organic traffic trend, or Google indexing status is claimed. Search Console, Analytics account settings, Business Profile ownership, and donor-provider conversion data were not available. Search results contained the site and some PDFs; that does not establish comprehensive indexing or ranking.

All four clubhouses have empty descriptions. | Use a shared metadata include with page-specific descriptions and safe fallback text; give priority pages explicit SEO copy. | More useful search snippets and clearer page context. |

Descriptions improve snippet usefulness; their presence is not a direct ranking guarantee. A missing H1 is a clarity issue, not proof of a Google penalty. Google can select snippets from page text and can choose a canonical different from the site's hint.

## Draft homepage text

Suggested visible H1: **Boys & Girls Clubs of Coachella Valley**

Suggested introduction: **A safe place for young people to learn, grow and build their future. Explore our programs in education, arts, sports, leadership and life skills, and find a clubhouse in Indio, Coachella, La Quinta or Mecca.**

Suggested adjacent links: **Find your local clubhouse** → `/our-clubs`; **Explore youth programs** → `/programs`; **Support local youth** → `/ways-to-give`.

Add an HTML location section listing each existing clubhouse, its verified address and telephone number, and a descriptive link to its detail page. Transcribe mission/vision text accurately from the approved organization wording. Keep fundraising graphics where they help visitors, but give important information a readable HTML equivalent. Confirm current age eligibility, fees, application process, transportation, summer availability, and hours before adding those details.

## Content and local SEO opportunities

Prioritize the existing club pages for searches about youth and after-school programs in Indio, Coachella, La Quinta, and Mecca. These are suggested search intents based on the site's services, not measured keyword demand. Each page should answer the parent's next questions: who can join, how to apply, current hours, what programs are available there, what it costs, and who to call. Avoid repeating a generic paragraph on all four pages.

Review the administrative office separately from public clubhouses. Confirm each eligible location's Google Business Profile, accurate category, address, phone, opening hours, and direct clubhouse URL. Keep details consistent with the website. Review management and location photos can be handled after access and eligibility are established; no Business Profiles were edited in this audit.

Publish useful HTML summaries of current impact reports and newsletters with links to their PDFs. Sixty PDFs appear in the sitemap, including historical calendars and giving documents. PDF indexing is not inherently a problem; distinguish current resources from archives and remove obsolete material from discovery only where appropriate. Do not blanket-noindex all PDFs or delete old resources without checking links and usage.

For fundraising, improve the Ways to Give page and current event pages with clear purpose, date/status, location, organizer, and donation/registration steps. Add Event structured data only to actual eligible events with accurate, visible dates and venues. Do not invent event dates to fill missing fields or mark past events as upcoming.

## Proposed first implementation

This is a bounded update to the existing Jekyll metadata and page templates:

1. Create a shared SEO include used by `root/jekyll/_includes/head.html`, `home-head.html`, and `collection-head.html`. Resolve SEO title, plain-text description, canonical URL, and image once; escape attribute content and serialize JSON safely. Support explicit SEO fields so descriptions used as long visible copy are not accidentally replaced.
2. Add the draft SEO fields to the homepage, core pages, and four clubhouse entries. Use content-based fallbacks for other pages. Correct Open Graph and Twitter values, including `page.hero` image fallback.
3. Use `/` as the homepage canonical and existing extensionless top-level navigation URLs as preferred URLs. Keep current `.html` collection URLs. Generate matching sitemap entries via Jekyll-supported sitemap metadata and keep existing URLs reachable. Evaluate redirects after a deployed preview; no global URL migration in the initial change.
4. Add a visible homepage H1/introduction and an HTML section linking to the four clubhouses. Add Organization JSON-LD using confirmed public details.
5. Exclude `/admin/` from the sitemap and add noindex to the CMS shell. Correct the three broken links after destination validation. Add descriptive logo alt text, iframe titles, and below-the-fold lazy loading/dimensions where source assets establish the dimensions.

Compression/replacement of image graphics, expanded location copy, GA4 configuration, Business Profile work, and event editorial cleanup can follow as separate improvements. Their effect and factual content need additional validation.

Verification should render the production Jekyll output and assert that priority pages each have one nonempty description, one correct canonical, valid social-image URLs, and valid JSON-LD. Check sitemap consistency and CMS exclusion, verify replacement links, inspect desktop/mobile layout, and validate the homepage markup using Google's tools. On a deployed preview, verify redirect behavior and perform mobile performance measurements. After release, use Search Console URL Inspection and submit the sitemap.

The current checkout has a build-environment constraint: `.nvmrc` specifies Node 14.21.3, but the active Node is 22.15.0 and the installed Node Sass 4.14.1 fails its runtime compatibility check. `bundle check` reports Ruby dependencies satisfied. A successful full build was not established. Resolve or use a compatible build runtime before claiming a deployable optimization; dependency modernization is outside this initial metadata change.

## Measurement after release

Establish a Search Console baseline for clicks, impressions, click-through rate, queries, and landing pages before changes. Segment organization-name queries from discovery queries about youth programs and cities. Compare subsequent 28-day periods and consider seasonality rather than attributing every change to SEO.

Verify GA4 receives page views and useful events: clubhouse phone clicks, membership application opens/downloads, donation outbound clicks, and event registration outbound clicks. An outbound donation click is not a completed donation. Track completed donations only with supported donor-provider integration and reconciliation. Use Search Console's Core Web Vitals report or verified field data for actual user performance.
